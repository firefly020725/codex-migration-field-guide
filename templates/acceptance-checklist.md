# 本地会话迁移验收清单

这是人工填写模板，不是执行授权、官方 API 或要求每次迁移重复所有测试的标准。先选择适合的官方能力或经过审查的工具，再用此表明确你实际需要保留什么。

## 目标和范围

- [ ] 说明目的：远程访问原电脑、持续同步、导出阅读、一次性迁出或合并到已有环境。
- [ ] 记录源与目标的应用版本、操作系统、执行用户、实际数据目录和项目目录。
- [ ] 区分相同账号、相同 ID 与相同存储实例；不依赖账号登录来推断本地历史存在。
- [ ] 列明目标已有数据、禁止覆盖范围和项目当前暂停断点。
- [ ] 明确最终工作位置；测试用户不是默认正式位置。
- [ ] 列出需要保持的层次：普通文件、会话内容/身份、媒体、权限、项目关系、完整系统状态。

## 备份与最小演练

- [ ] 选择能产生一致快照的备份方法，明确数据库及外部文件的时间点关系。
- [ ] 若采取本例的文件级冷复制，先关闭相关写入者并保留现存配套文件。不要单独复制运行中的主数据库，也不要把 WAL/SHM 当垃圾先删掉。
- [ ] 验证备份可读；需要恢复保证时，按承诺的范围在新位置做恢复演练。
- [ ] 从无父依赖的普通主会话小样本开始，保存消息原文和身份基线。
- [ ] 用真实预期输入方式续聊一次，验证历史与重开保留；跨聊天投递不要按普通输入项计数。

SQLite 的 WAL 是数据库持久状态的一部分；在线备份 API 可以为数据库生成一致副本，但不会自动打包 Codex 的其他文件或媒体。[SQLite WAL](https://www.sqlite.org/wal.html)、[SQLite Backup API](https://www.sqlite.org/backup.html)

## 接入前

- [ ] 冻结清单包含路径、字节数、哈希、会话关系和外部依赖；既有缺失单列。
- [ ] 检查磁盘空间和卷身份；预留目标投影及备份空间。
- [ ] 同 ID 分别归类：完全相同、源为目标前缀、目标为源前缀、内容分叉、身份不明。不自动把任何类别等同于可覆盖。
- [ ] 明确读写范围、禁止覆盖的对象、提交日志与中断后如何判定已完成部分。
- [ ] 备份覆盖目标既有数据；源数据库不直接覆盖已有目标数据库。

## 接入后

- [ ] 新增文件及既有文件的差集符合计划；哈希正确，原数据保留。
- [ ] 从正式客户端定位原 ID，检查原生历史和当前状态；不单凭侧栏缺席或 `notLoaded` 下结论。
- [ ] 对允许追加的记录检查原始前缀与新增后缀；分清旧失败状态与新动作。
- [ ] 用户手动发送一次限定任务，检查上下文、消息身份和实际项目依赖。
- [ ] 验证一次正常退出重开；已有证据足够且无新变化时，不重复整套检查。
- [ ] 用原生项目功能确认归属；不要为满足单个数据库字段预期而手工修库。

## 媒体

- [ ] 分别记录：文件是否存在、字节是否正确、引用是否可解析、原气泡是否可见。
- [ ] 映射有身份或哈希依据；同名不能证明等价。
- [ ] 先验证一张上传图和一张生成图，再扩大到固定清单。
- [ ] 在原聊天验收缩略图、内联主图和大图，独立打开文件不替代此项。
- [ ] 明确全量文件验证与界面抽查的区别；记录真实抽样范围。
- [ ] 补找回的媒体另加记录，不改写原冻结时点的缺失事实。

## 收尾

- [ ] 将完成项、剩余缺失、工具限制和未验证能力写明。
- [ ] 确认目标原有数据仍可用。
- [ ] 指定后续权威分支，禁止用后来增长的来源记录覆盖它。
- [ ] 把最终决定通过普通交接消息交到目标会话，获得接收确认。
- [ ] 明确迁移完成是否包含复工。本案例中不包含。
- [ ] 备份、兼容图片目录与失败现场的后续清理另定范围，不随迁移成功自动删除。
